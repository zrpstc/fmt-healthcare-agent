# 默认决策与偏离说明

1. **章节映射按代码实际情况处理**：仓库当前只有 13 个专业版章节，行动建议对应第 13 章，而不是任务文本中的第 14 章；“更多线索”对应第 9、10、12 章（生态、肠脑轴、专项代谢），第 11 章疾病风险模型不进入消费者版。该偏离不改变专业版输出。

2. **样本别名**：优先使用 metadata.name；没有时使用“样本 + 样本 ID 最后一个下划线后的片段”，例如 `ZYMO_D6331` → “样本 D6331”。没有使用 `sid[-6:]`，因为它会得到 `_D6331`，可读性差。

3. **质控状态缺失**：报告 metadata 中没有显式 `qc_status`。按专业版的 `qc_failed` 逻辑，只有明确 failed/未通过才视为失败；缺失时不阻止“未检出”表述，但记录为默认假设。

4. **参考派生资产缺失**：cMD bundle 没有 `consumer_derived` 资产，因此有益菌类别、集中度参考档位无法计算。正文只给数值，不伪造档位；相关项登记到 omissions。组成典型度使用报告已有的 `healthy_comparison.typicality`。

5. **专业版单通路 bug 保留但消费者版修复**：`chapter_two.redundancy_rows` 只选一条代表通路；消费者版 `functions.aggregate_category` 汇总类别下所有已观测通路。专业版代码未改，作为后续事项记录。

6. **丁酸贡献菌的分层缺口**：样本的 PWY-5676、CENTFERM 等没有分层贡献；P163 只有核梭杆菌。消费者版汇总了全部通路，并以重点菌面板补入普拉梭菌、罗氏菌等已知产丁酸类别成员；同时保留“分层注释覆盖有限”的事实，不把类别成员说成实测贡献。

7. **乳酸利用分层为空**：PWY-8086 只有 community 行，没有分层贡献。消费者版保留“基因通路已检出”，并用菌种特性补充罗氏韦荣球菌等乳酸利用菌，标注为菌种特性推断，不伪造基因分层。

8. **EC 注释只作补充**：平台的 `functional_modules` 状态为 invalid_input，没有正式 EC 模块。消费者版从 HUMAnN `utility_mapping` 的 UniRef→EC 映射补充贡献菌，只用于补充证据，不加入通路丰度或占比分母；映射不存在时自动跳过。

9. **术语库格式**：环境没有 PyYAML。`knowledge_base/consumer_*.yaml` 写成 JSON（JSON 是 YAML 的子集），加载器先尝试 JSON，必要时再尝试 PyYAML；这样不新增运行时依赖。

10. **LLM 润色未接入运行时**：平台报告模型配置没有随报告持久化，构建器默认全部使用规则文案。`narrative.polish` 保留校验钩子，未配置或失败时规则文案照常输出。

11. **知识子图不足**：很多 topic 的原始子图清洗后少于两条关系（例如耐药 topic 只有“位于”关系）。消费者版隐藏该子图并登记 omissions，不为了“每节一张图”而保留无证据的图。可用的子图集中在组成、多样性分工、重点菌、营养、代谢产物和更多线索。

12. **公开下载不暴露样本 ID**：分享页的下载链接改写为 `/backend/api/share/{token}/downloads/{kind}`；公开 JSON 中 `sample.sample_id` 换成别名，且不含服务器路径或内部服务 URL。

13. **截图环境**：Node 18 + Playwright browser 下载被网络阻断（ECONNREFUSED 443），无法按 Playwright 生成 PDF。使用 OpenCode 内置 Chromium 生成网页截图；打印 PDF 提供人工验收清单。

14. **千分位计数例外**：产品明确要求参考人数写 `3,537`，因此正文有效数字扫描把千分位整数计数排除；百分比和测量值仍执行最多 3 位有效数字。
